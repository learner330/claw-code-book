# 第1章 什么是 Agent：从工具调用到自主闭环

## 本章概览

本章建立 Agent 的认知框架。在进入任何具体实现之前，先回答三个问题：Agent 的本质是什么，它与传统软件的差异在哪里，以及支撑 Agent 运转的核心抽象是什么。

## 1.1 Agent 的定义

Agent 是一个通过"感知-决策-执行-观察"闭环自主完成目标的软件系统。人类给出目标后，Agent 自行决定执行路径、调用工具、观察结果并迭代，不需要每一步都下达指令。

这个闭环有三个关键特征：

自主性。Agent 接收目标后拆解为子步骤并排序。人类说"修好这个 bug"，Agent 自己决定先读报错信息还是先定位代码，编译失败后再自主决定下一步。

工具中介。Agent 的所有动作都通过预定义的工具接口完成，不会直接调用底层系统 API。工具是 Agent 连接外部世界的唯一通道，工具列表决定了 Agent 的能力边界。

迭代执行。Agent 不是一次性执行完就结束。每一步执行后，它会观察结果（文件内容、命令输出、错误信息），结合原始目标判断是否需要继续，然后把结果喂回决策层进入下一轮。

```
目标输入 → [感知环境] → [LLM决策] → [执行工具] → [观察结果]
                                         ↓              ↓
                                    [调用工具]      [读取结果]
                                         ↓              ↓
                                    文件系统/Shell/网络
                                         ↑
                                    ←────┘
```

## 1.2 与传统软件的差异

传统软件有三种典型模式，都与 Agent 有本质区别：

请求-响应模式（HTTP API、RPC）。调用方发请求，服务返回响应，结束。每次调用独立无状态，上次调用不会自动影响下次。

命令式 CLI（git、curl）。一条命令对应一个固定动作，人类必须自己编排多步操作。`git add` 不会自动触发 `git commit`。

事件驱动系统（消息队列、Webhook）。被动响应外部事件，逻辑由回调函数实现，执行路径在编译期确定。

| 维度 | 请求-响应 | 命令式 CLI | 事件驱动 | Agent |
|------|----------|-----------|---------|-------|
| 触发方式 | 外部请求 | 人类输入 | 外部事件 | 目标下达 |
| 控制流 | 单次返回 | 人类编排 | 回调链 | LLM 动态决策 |
| 状态管理 | 无状态 | 文件系统 | 消息偏移量 | 对话上下文 |
| 执行路径 | 编译期确定 | 人类确定 | 编译期确定 | 运行时动态确定 |
| 错误处理 | 返回错误码 | 人类处理 | 重试/死信 | 自主判断并修正 |
| 终止条件 | 响应发出 | 命令完成 | 队列排空 | LLM 判断目标达成 |

Agent 的特殊之处在于：它的执行路径在运行时由 LLM 动态决定，而且它会自动迭代直到判断目标达成。这意味着相同的输入可能产生不同的执行序列，执行过程中出现错误不会直接退出，而是被纳入下一轮决策。

## 1.3 核心抽象：工具

工具是 Agent 唯一允许的外部交互方式。LLM 不直接读写文件、不直接执行命令——它输出"调用 X 工具、参数为 Y"的结构化请求，由 Agent 执行层完成实际操作。

这个设计带来两层隔离：

能力边界隔离。工具列表是 Agent 的能力全集。如果工具列表里没有"网络请求"，LLM 就无法访问网络，无论它多想发 HTTP 调用。这种设计让能力边界可枚举、可审计。

安全隔离。工具执行层可以在实际调用前插入审查。LLM 请求删除文件时，执行层可以检查权限策略、要求人工确认、或者直接拒绝。

一个工具的定义通常包含：名称（LLM 调用的标识）、描述（让 LLM 理解工具用途）、参数 Schema（LLM 需要提供的输入）、执行函数（实际操作的实现）。

## 1.4 核心抽象：LLM 作为决策引擎

Agent 的"大脑"是一个大语言模型。LLM 接收三类输入：

系统提示词（System Prompt）。定义 Agent 的角色、行为准则、可用工具列表、输出格式约束。系统提示词在会话开始时注入，全程有效。

对话历史（Messages）。包括人类输入、LLM 之前的回复、工具调用及其结果。LLM 的每次决策都基于完整的历史上下文。

当前轮次输入。用户新发的一条消息，或者上一轮工具执行返回的结果。

LLM 的输出有两种形式：文本回复（面向用户的最终回答）或工具调用请求（要求执行层执行某个操作）。当 LLM 输出工具调用时，Agent 执行工具并把结果追加到对话历史，再次请求 LLM 决策——这就是 Turn Loop 的驱动机制。

LLM 作为决策引擎的缺点是它的输出是概率性的。相同输入可能产生不同输出，可能在某些上下文中做出不符合预期的决策。这引出了 Agent 工程中两个重要的设计约束：可观测性（记录完整决策过程以便事后审计）和可中断性（人类能在关键时刻接管或终止）。

## 1.5 Turn Loop：Agent 的执行引擎

Turn Loop 是 Agent 的核心循环。它的每一次迭代包含四个步骤：

1. 收集上下文：组装系统提示词 + 对话历史 + 当前轮次输入
2. 请求 LLM：将上下文发送给 LLM，等待回复
3. 解析决策：判断 LLM 输出是文本回复还是工具调用
4. 执行并反馈：如果是工具调用，执行工具并把结果写入对话历史，回到步骤 1

循环的终止条件是 LLM 输出纯文本回复（不再请求任何工具调用）。此时 Agent 把文本回复返回给用户，等待下一次输入。

```
开始迭代 → 收集上下文 → 请求LLM → 解析输出
                                      │
                    ┌─────────────────┼─────────────────┐
                    ↓                                   ↓
              [工具调用]                            [文本回复]
                    ↓                                   ↓
              执行工具 → 结果写入历史 → 回到开始      返回结果（循环结束）
```

Turn Loop 与 HTTP 请求处理的本质区别是：HTTP 处理完一个请求就销毁上下文，Agent 在循环之间保持对话状态。这意味着 Agent 需要设计会话持久化机制——用户关闭终端后再次打开，Agent 需要恢复之前的对话历史，继续工作。

## 1.6 Agent 的工程挑战

LLM 的自主性和概率性带来了传统软件不面临的问题：

权限控制。传统 CLI 中，用户输入 `rm -rf` 是一个明确的意图表达。Agent 可能在 Turn Loop 中自主决定"清理临时文件"，而这个决定可能是错误的。Agent 工程需要设计分级权限机制，在工具执行前做安全审查。

可观测性。Agent 的决策过程不透明——它调用了哪些工具、为什么调用、执行结果是什么——这些信息对事后调试和审计至关重要。Agent 工程需要完整记录每一步决策。

成本控制。每次 Turn Loop 迭代都会消耗 LLM API 额度。工具返回的结果过长会浪费 token，LLM 陷入死循环会持续扣费。Agent 工程需要设计 token 预算、最大轮次限制、结果截断策略。

错误恢复。LLM 可能生成格式不正确的工具调用参数，工具执行可能超时或报错。Agent 工程需要决定哪些错误可以自动重试、哪些需要返回给 LLM 让其修正、哪些应该终止循环。

会话管理。长时间的对话会累积大量历史，超出 LLM 的上下文窗口。Agent 工程需要设计压缩策略，在不丢失关键信息的前提下缩减历史长度。

## 1.7 Agent 的典型形态

Agent 的工程形态因场景而异：

编码助手。在 IDE 或终端中辅助开发者，能读写文件、执行命令、搜索代码。特点是工具集围绕文件系统和 Shell 操作，强调对项目上下文的理解。

研究助手。联网搜索、阅读文档、整理信息。特点是工具集围绕网络访问和文档处理，强调信息综合能力。

运维助手。监控告警、执行运维操作、生成报告。特点是工具集围绕基础设施 API，强调操作的幂等性和安全性。

自动化流水线。在 CI/CD 或定时任务中执行，无人值守。特点是输入确定性高，错误处理策略保守，强调可重放性。

这些形态共享同一个闭环结构：感知、决策、执行、观察。差异在于工具集和约束条件的组合。

## 小结

Agent 是一个自主的感知-决策-执行-观察闭环系统，与传统软件的请求-响应或命令执行模式有本质区别。工具是 Agent 连接外部世界的唯一通道，LLM 是动态决策引擎，Turn Loop 是驱动迭代的核心循环。

Agent 工程面临权限控制、可观测性、成本控制、错误恢复、会话管理五项挑战，这些挑战在传统软件中不存在或不突出。
